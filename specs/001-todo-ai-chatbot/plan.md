# Implementation Plan: Todo AI Chatbot

**Branch**: `001-todo-ai-chatbot` | **Date**: 2025-01-09 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/001-todo-ai-chatbot/spec.md`

## Summary

Build an AI-powered conversational todo management system that allows authenticated users to create, read, update, and delete tasks through natural language. The system uses OpenAI Agents SDK for intent detection and reasoning, MCP (Model Context Protocol) tools for all data operations, and maintains a fully stateless backend architecture with all state persisted in Neon PostgreSQL. The frontend provides a ChatGPT-style widget interface with streaming responses via SSE.

## Technical Context

**Language/Version**: Python 3.11+ (backend), JavaScript/TypeScript (frontend widget)
**Primary Dependencies**:
  - Backend: FastAPI, OpenAI Agents SDK, Official MCP SDK, SQLModel, Better Auth
  - Frontend: OpenAI ChatKit, chatbot-widget-creator Agent Skill
**Storage**: Neon Serverless PostgreSQL (SQLModel ORM)
**Testing**: pytest (backend), frontend testing framework TBD
**Target Platform**: Web application (modern browsers with JavaScript)
**Project Type**: web (backend API + frontend widget)
**Performance Goals**:
  - Chat responses (including tool execution) < 5 seconds p95
  - Database queries < 500ms p95
  - Support 1000 concurrent users
**Constraints**:
  - Stateless backend (no in-memory session state)
  - AI agent MUST only access data through MCP tools
  - User identity enforced at all layers
  - Horizontal scalability required
**Scale/Scope**:
  - 5 core MCP tools (add, list, update, complete, delete tasks)
  - 3 database tables (Task, Conversation, Message)
  - 1 chat API endpoint
  - Support for conversations up to 500 messages
  - Typical users < 1000 active tasks

## Phase 0: Research & Technology Decisions

### Research Topics

1. **OpenAI Agents SDK Integration**
   - Question: How to integrate OpenAI Agents SDK with custom MCP tools?
   - Decision: Use Agents SDK's tool registration mechanism to expose MCP tools as callable functions
   - Rationale: Agents SDK natively supports OpenAI-compatible function calling; MCP tools can be wrapped as Python callables

2. **MCP SDK for Tool Implementation**
   - Question: What's the official MCP SDK pattern for stateless tools?
   - Decision: Use `@mcp_tool` decorator pattern with explicit user_id parameter in all tools
   - Rationale: Decorator pattern is standard in MCP SDK; explicit user_id ensures security boundary

3. **Streaming Responses via SSE**
   - Question: How to implement SSE streaming from FastAPI to frontend widget?
   - Decision: Use `fastapi.responses.StreamingResponse` with `text/event-stream` content type
   - Rationale: Native FastAPI support; compatible with chatbot-widget-creator's SSE client implementation

4. **OpenRouter as OpenAI-Compatible API**
   - Question: How to configure OpenAI Agents SDK to use OpenRouter instead of direct OpenAI API?
   - Decision: Set `base_url` to OpenRouter's endpoint and pass API key in headers
   - Rationale: OpenRouter provides OpenAI-compatible interface; avoids subscription dependency for hackathon

5. **SQLModel with PostgreSQL**
   - Question: Best practices for SQLModel relationship definitions and query optimization?
   - Decision: Use explicit relationship definitions with proper foreign keys; add indexes on user_id and conversation_id
   - Rationale: SQLModel (built on SQLAlchemy 2.0) provides type-safe ORM; indexes critical for query performance (< 500ms p95 goal)

6. **Stateless Conversation Context Loading**
   - Question: How to efficiently load conversation history on every request without performance degradation?
   - Decision: Implement pagination for conversations > 100 messages; cache recent conversations per user with short TTL (60s)
   - Rationale: Balances statelessness requirement with performance goals; pagination prevents loading massive histories

7. **Better Auth Integration**
   - Question: How to extract user_id from Better Auth JWT in FastAPI endpoints?
   - Decision: Create FastAPI dependency that validates JWT and extracts user_id from session
   - Rationale: Dependency injection is FastAPI best practice; reusable across all authenticated endpoints

8. **Error Handling for MCP Tool Failures**
   - Question: How should agent handle MCP tool failures (database down, validation errors)?
   - Decision: MCP tools raise descriptive exceptions; agent catches and formats user-friendly messages
   - Rationale: Separation of concerns (tools report errors, agent handles communication)

## Risk Mitigation

| Risk | Mitigation Strategy |
|------|---------------------|
| AI intent detection accuracy | Comprehensive system prompt with examples; confirmation messages; user feedback loop |
| Performance with large conversations | Pagination for >100 messages; short-term caching (60s TTL); database indexes |
| MCP + OpenAI SDK integration complexity | Early proof-of-concept; fallback to simpler tool invocation if needed |
| Statelessness vs UX | Streaming SSE for responsiveness; optimistic UI updates where safe; fast DB queries |
| Database connection failures | Retry logic with exponential backoff; graceful error messages; health monitoring |
