## Core Entity: Task

### Task Entity Definition

```python
from dataclasses import dataclass
from datetime import datetime
from enum import Enum

class TaskStatus(Enum):
    """Task completion status."""
    PENDING = "pending"
    COMPLETED = "completed"

@dataclass
class Task:
    """Represents a single todo item."""
    id: int                          # Unique identifier (auto-incremented)
    description: str                 # Task description (1-200 characters)
    status: TaskStatus               # PENDING or COMPLETED
    created_at: datetime             # Timestamp of creation

    def __post_init__(self):
        """Validate and normalize task data on creation."""
        # Strip leading/trailing whitespace
        self.description = self.description.strip()

        # Validate description length
        if len(self.description) == 0:
            raise ValueError("Task description cannot be blank")
        if len(self.description) > 200:
            raise ValueError("Task description must be 200 characters or less")
```

| Field | Type | Constraints | Validation | Description |

| `status` | `TaskStatus` | PENDING or COMPLETED | Enum validation | Task completion state |
| `created_at` | `datetime` | Not null | Auto-generated on creation | Task creation timestamp |

## State Transitions

### Task Status Lifecycle

```text
┌─────────────┐
│   CREATED   │ (status: PENDING)
└─────────────┘
       │
       ▼ (complete_task)
┌─────────────┐
│  COMPLETED  │ (status: COMPLETED)
└─────────────┘
       │
       ▼ (delete_task)
┌─────────────┐
│   DELETED   │ (removed from storage)
└─────────────┘
```

### Valid Transitions

| From | To | Method | Validation |
|------|---|--------|------------|
| PENDING | COMPLETED | `complete_task(task_id)` | Task must exist |
| PENDING | DELETED | `delete_task(task_id)` | Task must exist |
| COMPLETED | DELETED | `delete_task(task_id)` | Task must exist |
| COMPLETED | PENDING | *Not supported in Phase 1* | N/A |

**Note**: Task "un-completing" (COMPLETED → PENDING) is out of scope for Phase 1.

## Validation Rules

### Task ID Validation

| Rule | Description |
|------|-------------|
| Uniqueness | Each task ID must be unique within the session |
| Auto-increment | IDs are generated sequentially (1, 2, 3, ...) |
| Positive | Task IDs are positive integers (> 0) |

### Description Validation

| Rule | Description | Error Message |
|------|-------------|---------------|
| Not empty | Description cannot be empty or whitespace-only | "Task description cannot be blank" |
| Max length | Description cannot exceed 200 characters | "Description too long (max 200 characters)" |
| Trimmed | Leading/trailing whitespace is removed | (automatic, no error) |

### Status Validation

| Rule | Description |
|------|-------------|
| Enum values | Status must be PENDING or COMPLETED |
| Initial state | New tasks are created with PENDING status |
| Already complete | Cannot complete an already-completed task (warning) |

## Storage Schema (In-Memory)

### Data Structure

```python
# In-memory storage representation
class InMemoryStorage(StorageInterface):
    def __init__(self):
        self._tasks: List[Task] = []  # List of Task objects
        self._next_id: int = 1         # Next ID to assign
```

### Collection Semantics

| Operation | Behavior | Time Complexity |
|-----------|----------|-----------------|
| Add task | Append to end of list | O(1) |
| Get all tasks | Return list reference (or copy) | O(1) |
| Get by ID | Linear search through list | O(n) |
| Update task | Find by ID, replace in place | O(n) |
| Delete task | Find by ID, remove from list | O(n) |

**Note**: O(n) operations are acceptable for Phase 1 scale (<1000 tasks, <200ms target).

## Persistence Strategy (Phase 1)

### No Persistence

**Design Decision**: Tasks are stored in memory only and lost on program exit.

**Rationale**:
- Constitution requirement: "No file or database persistence in Phase 1"
- Simplifies Phase 1 implementation
- Validates core user interactions before adding persistence complexity

**Data Lifecycle**:
```text
Program Start → Empty task list
     ↓
User creates tasks → Tasks in memory
     ↓
Program Exit → All tasks lost
```

**Future Phases**: Will add:
- Phase 2: File-based persistence (JSON)
- Phase 3: Database persistence (SQLite or PostgreSQL)
- Phase 4: Distributed persistence (Dapr state store)

## Type Hints & Interfaces

### Storage Interface

```python
from abc import ABC, abstractmethod
from typing import List, Optional

class StorageInterface(ABC):
    """Abstract interface for task storage implementations."""

    @abstractmethod
    def add(self, task: Task) -> None:
        """Add a task to storage."""
        pass

    @abstractmethod
    def get_all(self) -> List[Task]:
        """Return all tasks."""
        pass

    @abstractmethod
    def get_by_id(self, task_id: int) -> Optional[Task]:
        """Find task by ID. Returns None if not found."""
        pass

    @abstractmethod
    def update(self, task: Task) -> bool:
        """Replace existing task. Returns False if ID not found."""
        pass

    @abstractmethod
    def delete(self, task_id: int) -> bool:
        """Remove task by ID. Returns False if not found."""
        pass
```

### Task Service Interface

class TaskService:

## Edge Cases & Constraints

### Edge Cases

| Scenario | Behavior |
|----------|----------|
| Empty task list | `get_all_tasks()` returns empty list `[]` |
| Task not found | `get_by_id()` returns `None` |
| Duplicate ID | Storage prevents via auto-increment |
| Very long description | Truncate to 200 characters with warning |
| Special characters in description | Allowed (UTF-8 support) |
| Unicode characters in description | Allowed (UTF-8 support) |

### Constraints

| Constraint | Value | Rationale |
|------------|-------|-----------|
| Max tasks | 1000 (soft limit) | Performance target: <200ms operations |
| Max description length | 200 characters | Usability, display formatting |
| Task ID range | 1 to 1,000,000 | Practical limit for single-user system |
| Session duration | Until program exit | No persistence in Phase 1 |

## Summary

| Entity | Fields | Validation | Storage |
|--------|--------|------------|---------|
| Task | id, description, status, created_at | Length, emptiness, enum | In-memory list |

**Key Design Decisions**:
- `dataclass` for clean entity definition
- `Enum` for type-safe status values
- `StorageInterface` abstraction for Phase 2+ extensibility
- Multi-layer validation (entity, service, storage)
- No persistence in Phase 1 (memory-only)

**All decisions align with Constitution principles**:
- SOLID (Single Responsibility, Dependency Inversion)
- DRY (reusable validation functions)
- Modularity (separate model, service, storage layers)
